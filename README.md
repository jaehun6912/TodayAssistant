# 오늘의 비서

Android 기기에 동기화된 캘린더를 Android `CalendarContract`로 통합해 보여 주고,
Gmail·Outlook의 새 메일, Microsoft To Do의 할 일 브리핑과 특정 게시판 새 게시글 확인을
제공하는 비서 어플리케이션입니다.

> 일정·메일·할 일을 앱에서 절대 수정하거나 삭제하지
> 않으며, 계정 토큰과 수집한 데이터는 기기 내에만 저장됩니다.

## 기능

- 오늘의 일정과 다음 일정을 보여 주는 홈
- Samsung·Google·Microsoft/Exchange·로컬 캘린더의 향후 일정
- 일정마다 실제 캘린더 이름과 출처 라벨 표시
- 하단의 **오늘 / 메일 / 공지 / 할 일 / 설정** 화면 전환
- 조회 화면과 설정 화면을 분리하고 일정·메일·공지·할 일 설정을 한곳에 구성
- 캘린더 진단은 설정 또는 오늘 화면의 **캘린더 연결 상태 보기**에서 접근
- 런타임 `READ_CALENDAR` 권한 요청
- 기기의 모든 캘린더와 다음 원본 필드 표시
  - `_ID`
  - `CALENDAR_DISPLAY_NAME`
  - `ACCOUNT_NAME`
  - `ACCOUNT_TYPE`
  - `OWNER_ACCOUNT`
  - `VISIBLE`
  - `SYNC_EVENTS`
- Samsung / Google / Microsoft·Exchange / 로컬 계정 출처 라벨
- 캘린더를 누르면 `CalendarContract.Instances`로 지금부터 30일간의 일정 조회
- 반복 일정은 각 발생 건(instance)으로 표시
- 일정 쓰기·수정·삭제 기능 및 `WRITE_CALENDAR` 권한 없음

현재 버전: `1.5.0`

### UI 및 사용성

- 하단 메뉴를 일관된 벡터 아이콘과 한글 라벨로 구성
- 홈의 메일·공지·할 일 상태를 간결한 상태 배지 목록으로 표시
- 설정 첫 화면에서 기능별 켜짐 상태를 한눈에 확인
- 메일·공지·할 일 조회 화면에서 해당 기능 설정으로 바로 이동
- 화면 전체의 카드 모서리, 간격, 밝은 화면·어두운 화면 색 대비 통일
- 비어 있음·오류·권한 안내 문구를 행동 중심으로 개선
- 장식용 화살표와 아이콘이 화면 읽기 기능에서 중복 낭독되지 않도록 처리

### 새 메일 브리핑

- Microsoft Graph `Mail.ReadBasic`과 Gmail API `gmail.metadata`로 계정 직접 확인
- 발신자·제목·수신 시각만 조회하고 본문·미리보기·첨부파일은 조회하지 않음
- MSAL 단일 계정 로그인과 안전한 토큰 보관 사용(비밀번호·토큰을 저장하지 않음)
- 첫 연결은 최근 메일을 기준선으로만 저장하여 기존 메일 알림 폭주 방지
- 이후 새 메일만 요약 대기 목록에 추가하고 수동·예약 시각에 직접 동기화
- Gmail도 Google 계정에서 직접 동기화하고 최초 연결 시 현재 상태를 기준선으로 저장
- Android 알림 접근 방식은 직접 연결하지 않은 계정의 보조 방식으로 유지
- 기본 요약 시각 `08:00 / 13:00 / 19:00`
- 메일 요약 차수 추가·변경·삭제
- Gmail·Outlook을 알림 대상에서 개별 선택
- 설정 시각까지 모인 새 메일이 있을 때만 한 알림으로 요약
- 앱 안에서 요약 대기 목록 확인 및 **지금 알림** 시험
- 재부팅, 앱 업데이트, 시각·시간대 변경 후 자동 재예약

직접 연결한 계정은 같은 메일 앱 알림을 중복 수집하지 않습니다. 직접 연결하지 않은
계정만 Android 알림 접근을 보조 입력으로 사용할 수 있습니다.

### Samsung Reminder / Microsoft To Do 브리핑

- Samsung Reminder 자체의 데이터를 불러오는 API는 존재하지 않아 **Microsoft To Do와 동기화** 기능을 공식 연결 경로로 사용
- Microsoft Graph `Tasks.Read` 위임 권한만 사용하며 완료·수정·삭제 기능 없음
- Microsoft To Do의 모든 목록과 미완료 항목 표시
- 목록별 요약 포함·제외 선택
- 기한 또는 미리 알림 시각이 오늘까지인 항목을 한 알림으로 요약
- 기본 요약 시각 `08:00 / 19:00`, 차수 추가·변경·삭제 가능
- 앱에서 **지금 동기화**, **지금 알림** 시험 가능
- 개별 할 일 알림은 Samsung Reminder가 계속 담당
- 재부팅, 앱 업데이트, 시각·시간대 변경 후 자동 재예약

### 공지 모니터링

- 게시판별 모니터링 대상 선택 및 수동 **지금 확인**
- 설정에서 HTTPS 게시판 목록 주소를 직접 추가·수정·삭제
- 기본 제공 사이트는 개별 켜기·끄기를 지원하며 기본적으로 수정 잠금
- 기본 사이트는 잠금을 해제한 뒤 이름·주소를 수정하고 다시 잠글 수 있음
- 수정된 기본 사이트는 앱의 원래 이름·주소로 복원 가능
- 직접 추가 사이트는 저장 즉시 게시물 분석을 시도하고 첫 성공 결과를 기준선으로 저장
- 사용자가 기능을 켜면 약 1시간 간격으로 자동 확인
- 게시물 고유 번호를 저장해 새 글만 알림
- 최초 확인 결과는 기준 목록으로 저장하므로 기존 글 알림이 한꺼번에 울리지 않음
- 게시판별 최근 결과를 기기에 보관해 일시적인 통신 오류에도 마지막 목록 표시
- 한 게시판의 확인이 실패해도 나머지 게시판은 계속 확인
- 공지를 누르면 원본 게시글을 기기의 기본 설정 브라우저로 열기

자동 확인은 Android의 배터리 정책을 따르는 일반 알람을 사용하므로 정확히 매시 정각에
실행되는 기능은 아닙니다. 인터넷 연결이 필요하며, 게시판 구조가 바뀌면 해당 출처의
목록 분석을 조정해야 할 수 있습니다.

직접 추가는 날짜와 게시글 링크가 일반 HTML에 포함된 공개 게시판을 대상으로 합니다.
로그인이 필요하거나 자바스크립트로만 목록을 만드는 사이트는 별도 분석 규칙이 필요할 수
있습니다. 보안을 위해 `https://` 공개 주소만 등록할 수 있습니다.

### 오늘 일정 요약 알림

- Android 13 이상에서 사용자가 기능을 켤 때 `POST_NOTIFICATIONS` 권한 요청
- 사용자가 선택한 시각에 당일 전체 일정을 한 알림으로 요약
- 알림 차수를 필요한 만큼 추가·변경·삭제
- 같은 시각의 중복 알림 등록 방지 및 시간순 자동 정렬
- 진단 화면과 같은 캘린더 목록에서 알림 대상을 개별 선택
- 공휴일·법정기념일·절기와 세시풍속 등 불필요한 캘린더 제외 가능
- 전체 선택·전체 해제 지원
- 선택한 캘린더를 메인 화면의 오늘·다음·다가오는 일정에도 동일하게 적용
- 메인 화면에서 표시 대상 설정으로 바로 이동하고 선택 수 표시
- 진단 화면은 점검을 위해 선택과 관계없이 전체 캘린더 유지
- 알림 시점에 Calendar Provider를 다시 조회해 최신 당일 일정 반영
- 일정이 없는 날에도 “오늘 일정 없음” 안내
- 재부팅, 앱 업데이트, 시간·시간대 변경 후 다음 요약 알림 자동 재예약
- 배터리 정책을 따르는 일반 알람 사용(정확한 알람 특별권한 없음)

개별 일정 시작 전 알림은 만들지 않습니다. 해당 기능은 Samsung 캘린더에 맡기고,
이 앱은 하루 일정 브리핑만 담당합니다.

Samsung의 계정 유형 문자열은 기기와 One UI 버전에 따라 다를 수 있습니다. 앱은
`com.osp.app.signin`, `samsung`, `scloud` 계열을 “Samsung 계정 후보”로 표시하면서
원본 `ACCOUNT_TYPE`도 그대로 보여 줍니다.

## 빌드

1. 최신 안정 Android Studio에서 이 폴더를 엽니다.
2. SDK Manager에서 Android SDK Platform 36과 SDK Build-Tools 36.0.0을 설치합니다.
3. Gradle JDK를 Android Studio의 내장 JDK 17 이상으로 지정합니다.
4. 프로젝트 동기화 후 **Build > Build APK(s)** 를 실행합니다.

명령줄에서는 프로젝트 루트에서 다음을 실행할 수 있습니다.

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug
```

APK 위치:

```text
app/build/outputs/apk/debug/app-debug.apk
```

USB 디버깅이 켜진 Galaxy가 연결되어 있다면 다음처럼 설치할 수 있습니다.

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

계정 연동을 포함해 직접 빌드하려면 [OAuth 설정 안내](docs/OAUTH_SETUP.md)를 먼저
확인하세요. 저장소의 Microsoft 클라이언트 ID는 비밀키가 아닌 네이티브 앱 공개 ID지만,
복제한 앱은 자신의 패키지 서명에 맞는 Microsoft·Google OAuth 등록이 필요합니다.

최신 설치용 APK는 GitHub의 **Releases**에서 제공합니다. APK를 업데이트 설치하면
기존 앱 설정과 계정 연결이 유지됩니다.

## Galaxy 실기기 확인 순서

1. Samsung 캘린더 앱에서 Samsung 계정 캘린더가 동기화되고 표시되는지 확인합니다.
2. 이 앱을 실행하고 캘린더 읽기 권한을 허용합니다.
3. 목록에서 “Samsung 계정 후보” 또는 Samsung과 관련 있어 보이는 원본
   `ACCOUNT_TYPE`의 캘린더를 찾습니다.
4. 해당 캘린더를 눌러 앞으로 30일 일정이 표시되는지 확인합니다.

판정 기준:

- Samsung 캘린더 행과 일정이 모두 보이면 Samsung 계정 데이터가
  `Calendar Provider`에 노출되는 것입니다.
- 캘린더 행은 있지만 일정이 없으면 30일 내 일정 유무, `VISIBLE`, `SYNC_EVENTS`,
  Samsung 캘린더의 동기화 설정을 확인합니다.
- Samsung 관련 행 자체가 없으면 해당 One UI 구성에서 Samsung 계정 캘린더가
  일반 `Calendar Provider`에 등록되지 않았거나, 다른 프로필·보안 폴더에 격리됐거나,
  동기화가 꺼져 있을 수 있습니다.

`VISIBLE=0`인 캘린더는 Android가 `Instances` 행을 생성하지 않을 수 있으므로,
테스트할 캘린더는 Samsung 캘린더 앱에서 표시 상태로 두는 것이 좋습니다.
